Add versioned JSON codecs

OpenSpec change | Bead smithy-2qe.53 | 2026-10-27 | Proposed; implementation not started

A runtime-first JSON codec prepares one wire contract for checking, decoding and canonical encoding. Morphir v3 and v4 are the first acceptance target. See the proposal for motivation and scope.

Context and evidence

  • pkgs/smithy-validation/prepare.mbt snapshots reachable shapes, constraints and wire member names. Its validator assumes one-member object unions. view.mbt already exposes exact numbers and location-aware object fields, but synthetic array/scalar projections still need explicit source mapping.
  • pkgs/smithy-codegen-jsonrpc/description.mbt demonstrates prepared, detached contracts. The three language generators separately emit object-only union codecs. Their future integration must consume a contract, not re-read serialization traits.
  • pkgs/smithy-jsonschema/converter.mbt uses unionStrategy to choose schema rendering. That setting is not an application wire-format selector.
  • site/tour/lessons/38-morphir-values and 39-morphir-limits cover the current expanded-object subset and demonstrate rejected compact/v3 inputs. Existing cases without a profile remain valid compatibility tests.
  • Morphir's v3 reader uses tagged positional arrays; v4 adds compact scalar/list forms and expanded objects. Its versioned API keeps separate models and never migrates while reading. See the pinned authorities below.

Goals and non-goals

Keep logical shape and union-member identities independent of wire syntax. Prepare once, reuse bounded contracts, and preserve original JSON locations through projection. Make the supported representation language finite and testable. Behavioral requirements are in json-codecs and serialization-profiles.

This delivery does not generate new MoonBit/Python/Go types, replace Morphir's type checker, migrate IR versions, implement v1/v2 or add YAML/Ion encoders. Existing RPC protocols, Smithy's model JSON AST and default value validation keep their current behavior. A trait declaration alone does not imply that an exporter or protocol supports it.

Decisions

API-1. Prepare runtime codecs and expose detached contracts

Add pkgs/smithy-codec with a lightweight /contract package for profile definitions, typed encoding decisions and immutable contract snapshots. The runtime prepares a logical validator and wire plan together. Its public operations are conceptually prepare(model, root, profile, registry), check(text), decode(text) and encode(value); exact MoonBit signatures follow the checked package documentation.

ProfileId, member positions, validated tag names, adapter IDs and version selectors have boundary constructors. CodecValue retains semantic root/model identity and selected union member; it is not just a relabeled JSON string. Values can be constructed through validated builders as well as decoding. A value may be re-encoded under another profile of the same semantic contract, but a different version-specific root requires explicit conversion.

The module depends on smithy and smithy-validation. The validator must not import the codec module: composition, a location-aware view and minimal additive budget support prevent a module cycle. Detached contracts do not retain live mutable model maps. Alternative: generate language-specific codecs first. Rejected because it repeats interpretation across writers before the contract is proven.

CFG-1. Put rules in model profiles; configuration selects them

Provide versioned trait definitions under the extension namespace smithy.serialization. The proposed declarations are jsonProfiles on a document/root declaration, jsonEncoding on data shapes/members, and untagged on unions. jsonEncoding contains an optional base rule and named profile-specific rules; jsonProfiles registers identifiers, defaults, supported capabilities and version bindings. A non-service document declaration is sufficient.

Resolution is selected-profile shape/member rule, then selected-profile defaults, then applicable base serialization traits, then standard defaults. Same-precedence conflicts fail. A JSON plugin config selects profile, target or bundle and input/output locations; it cannot change tag layout or field positions. Supplemental Smithy files can attach traits with apply, so external model sources need not be rewritten. Persist profile definitions with the model, not in a generator-specific configuration file.

Continue to honor smithy.api#jsonName for effective wire member names. Alloy demonstrates useful existing encodings, but its general untagged decoding permits a broader search than the decision on smithy-2qe.34.22. The first implementation therefore uses the explicitly narrower extension trait instead of claiming full Alloy semantics. No new third-party Alloy dependency is required. Alternative: a global unionStrategy switch. Rejected because it cannot represent per-shape exceptions, multiple versions or portable reader/writer contracts.

WIRE-1. Use a finite representation vocabulary

RuleContract and preparation checks
External unionExactly one effective tag property containing a payload. This remains the ordinary default.
Internal unionDeclared discriminator; object-compatible targets only; discriminator and member names cannot collide.
Adjacent unionDistinct declared tag and content fields; payload may be scalar or composite.
Tag-first arrayTag at index zero; explicit target tuple positions. A tuple payload is spliced after the tag; an ordinary payload occupies one slot. Unit can declare tag-only output.
Untagged scalar unionDisjoint accepted JSON-kind sets after scalar policy is applied. Two numeric alternatives are rejected even when their ranges differ. This implements the runtime portion of the existing untagged decision.
Structure tupleExplicit member order and fixed arity, or a final rest-list member. Optional trailing fields need an explicit omission policy; ambiguous holes are refused.
DictionaryObject properties or two-element entry arrays. A declared key adapter preserves logical key identity and version-specific ordering. Duplicate normalized keys are rejected before map construction.

All metadata is parsed into typed alternatives once. Duplicate tags, unresolved member references, missing required positions, invalid rest fields and unsupported scalar kinds fail preparation. A complete node is interpreted against one declared form, not assembled by retrying different version families.

FORM-1. Separate compatible readers from canonical writers

Each shape can declare accepted reader forms and writer cases. Restricted form rules bind a whole scalar to one member, map positional fields/rest lists, unwrap a named tag, or supply explicitly declared empty/absent fields. Reader guards use JSON kind and declared structural/naming markers. Writer guards use declared member presence or empty values. Ambiguous dispatch is rejected; it never means first declaration wins. There is no embedded script, unrestricted expression interpreter or implicit coercion.

Morphir v4's bare name versus bare FQName uses explicit naming guards and the registered naming adapter. A bare array denotes Tuple; a Reference argument array remains inside its Reference wrapper. Empty attributes select compact output; nonempty attributes select the expanded payload. Reader-only aliases, such as attrs, never leak into canonical output. Supplying alias and canonical member together is an error. morphir-v4-expanded is an explicit output profile, not an inference from the input spelling.

Canonical output is stable and follows declared object-member order where required, including formatVersion before distribution. Whitespace and numeric lexeme spelling are not preservation guarantees; exact numeric value and version-specific logical equality are. Alternative: remember the original JSON and replay it. Rejected because it avoids validation of caller-created values and cannot provide deterministic canonical output.

ADAPT-1. Keep domain normalization in registered adapters

Expose an explicit host registry keyed by validated adapter IDs. Adapters normalize logical scalar shapes from declared JSON kinds, write their canonical forms, report relative source paths, charge expansion/work and optionally provide canonical map-key ordering. This allows a logical Name/FQName to accept supported legacy arrays without pretending that it is an unrestricted union or parsing provenance from rendered strings.

Provide a separate smithy-codec/morphir package for Morphir naming and version scalars. General codecs do not import it. The CLI/build host registers that known bundle's adapters explicitly when selected; other clients supply their registry through the library API. Model documents only name bindings already installed by their host. Missing bindings, invalid adapter output and normalized duplicate dictionary keys fail explicitly. Alternative: teach generic union code Morphir's separators and initialisms. Rejected because these are domain semantics.

Registered adapters are trusted host code and must honor the budget/expansion contract; registration is not a sandbox for arbitrary callbacks. The model cannot install an adapter or widen its declared capabilities.

VER-1. Dispatch once and retain exact version identity

A bundle pairs a version-field pointer and declared version scalar contract with nonoverlapping supported intervals, semantic root IDs and profile IDs. For Morphir, normalize integer baselines and strict three-component release strings according to its version contract. Initial bundle coverage follows the pinned MoonBit reference: [3.0.0,3.2.0) and [4.0.0,4.1.0), including the v3.1 Specs extension. v1/v2 are deliberately unsupported here.

The bounded, duplicate-aware text reader locates the version before interpreting the payload, regardless of object-field order. It does not assume the header is first, parse through binary64, or independently retry each version's decoder. An explicit selection must agree with an artifact's header. Individual node decoding instead uses an explicit root/profile and needs no envelope. Invalid syntax, unsupported release, missing version and family mismatch remain distinct.

The result retains both version-specific semantic root and exact normalized release. Encoding preserves that release and uses its canonical header spelling. Converting between v3 and v4 is a separate operation outside this implementation. The same-root compact/expanded change is a representation choice, not a semantic migration. Alternative: decode every version into the newest model automatically. Rejected because new constructs can lose information in historical output.

Use separate bindings for v3.0 and v3.1 where their allowed distributions differ: the pre-3.1 root must not accept the later Specs extension. Shared constituent shapes can be reused; selecting a broad v3 union and merely changing the version header is insufficient.

SAFE-1. Preserve precision, source paths and one request budget

Use the existing exact NodeNumber and duplicate-aware input boundary as the baseline, retaining number tokens and object occurrences before any map conversion. Map each projected logical member or position back to its original InstancePath. Reuse ValueView/LocatedObject where sufficient; add only the minimal public view or source-map support necessary for synthetic arrays/scalars. A failed nested tuple member must report its wire index, not a fabricated logical field path.

A request-scoped budget covers parsing, rule selection, adapter expansion, checking and output. Passing between phases transfers the remaining budget rather than resetting it. Preparation caches recursive shape contracts; walkers use explicit stacks. Decode returns no value on invalid or incomplete input. Encode validates root identity, shape constraints, representation guards and output bounds before returning bytes. File adapters publish only after success; a failed run leaves the destination intact.

Reuse scalar and structural constraint validation rather than reproducing it in every encoding branch. Test the source mapping and cumulative budgets at the composition boundary; do not assume existing location-aware object views prove every new form correct. This preserves the bounded Morphir behavior tracked by smithy-2qe.41.13.

CLI-1. Expose the same selection through CLI and build

Extend smithy validate value with explicit profile selection and a versioned-bundle mode. Add nested smithy codec canonicalize for decode/check/re-encode. Model and value inputs retain the CLI's existing stdin-once rule. A node uses --target and --profile; a full document uses --bundle, optionally constrained by an explicit profile. Incompatible selectors fail as usage errors.

Register a jsonCodec build plugin in apps/smithy/build_cli.mbt with check and canonicalize actions. The shared selection parser accepts a declared profile or bundle plus explicit input/output locations. Inputs resolve relative to the build configuration using the existing resource/path boundaries; outputs use the artifact writer's validated relative names. Both actions invoke the runtime contract and the same approved adapter registry as the CLI.

Valid complete checks exit 0; invalid values, malformed value input, incomplete work and I/O failure exit 1; invalid model preparation, configuration and unsupported selections exit 2. Structured diagnostics include validity, completeness, shape and original path. Canonical JSON is the only successful value output; diagnostics go to the selected diagnostic channel. Existing commands without profiles do not route through a new compatibility mode.

Do not add alternate-profile support to current generators/exporters in this delivery. Explicit requests for unsupported profile-aware generation/export must fail; ordinary standard-mode use is unchanged. No interpretation of JSON Schema unionStrategy as a wire selector is permitted.

CONF-1. Prove Morphir compatibility from pinned authorities

Add examples/morphir-codecs/ with complete version-specific Smithy roots for representative single-file artifacts, profile declarations, coverage inventory, sources/NOTICE and conformance cases. Model v3 attributes, definitions, patterns, values, types and dictionaries in their own contract. Model v4 extensions explicitly, including compact/expanded nodes. A catch-all Document standing in for a modeled node does not count as coverage; open extension/document-literal fields remain Document only where the source contract permits it.

Use the pinned v3 greeting artifact and v4 complete/books-and-records artifacts, plus naming, version and node cases. The newer authority pin below is independent of the tour's existing ab8d5c9 corpus. Do not edit that vendored directory manually. Compare checked cases with the corresponding upstream codec/conformance rules; a disagreement needs an explicit decision and a tracked issue, not a newly blessed golden output. Record structural/schema coverage separately from semantic type-checking and name resolution, which remain outside this codec.

Delivery and compatibility

  1. Introduce the optional codec module and trait loader with the current shared repository version. Register it in moon.work, module imports, version validation and publication inputs. Do not bump versions in this feature.
  2. Deliver object codecs with executable examples, then extend the same contract through additional representations, compact forms and adapters.
  3. Add version dispatch, CLI/build selection and the two Morphir acceptance bundles. Document all supported forms and intervals.
  4. Keep old validator invocations and default RPC output as regression baselines. Add opt-in passing Morphir tour cases without changing what default-profile failure cases mean.
  5. Enable use by selecting a profile. Roll back adoption by removing that selection and returning to the existing default API; no stored artifact is migrated automatically.

Implementation follows the task groups. Generator and profile-aware schema-export adoption can follow after the runtime contract and laws are stable; they are not prerequisites for this proposal's completion.

Verification

  • Every representation group lands preparation refusal cases, valid/invalid wire cases and checked API documentation alongside its implementation.
  • Check laws: successful complete check agrees with decode; decode after encode preserves logical value; canonicalize twice is stable; alternate-profile re-encoding preserves a compatible root; incompatible semantic roots refuse.
  • Exercise duplicate decoded keys, alias collisions, normalized dictionary keys, exact numbers, malformed version headers, adapter failure and cumulative limit exhaustion.
  • Run new library cases on wasm, wasm-gc, JS and native. Extend tests/features/value-validation.feature and add tests/features/json-codecs.feature; CLI console fences and build fixtures execute the documented commands.
  • Use the pinned Morphir conformance inventory for full artifacts and recursive node families; report any gaps by case ID and bead.
  • Integration gates are mise run format, mise run lint, mise run validate, mise run test, mise run test:scripts, mise run test:bdd, mise run test:cli, mise run tour:check, mise run site:check and mise run build. This planning step runs artifact checks only.
