Optimize release builds

Context · Goals · Decisions · Risks · Migration · Assessment

Context

See proposal. PR #91 final-head runs CI 40627681727 and Release 40627681732 are the comparison baseline. The existing dist script already separates build and pack. Windows qualification proves a different host contract from Zig cross-compilation.

Goals and non-goals

Reduce duplicated producer work and critical-path serialization. Preserve all backend builds, tests, Windows acquisition/CLI qualification, benchmark, tour, JSON-RPC, script tests, five-platform smoke, evidence trust and publication order. Do not deduplicate independent compiler checks or weaken executable Markdown contracts.

Decisions

BLD-1. One artifact owner per PR

CI owns PR dist and selected preview smoke. Remove Release's PR trigger. A shared category workflow runs once per caller and produces a same-run dist artifact. Release still calls it for release, nightly and manual execution. This avoids polling another workflow, foreign-run artifacts, token privilege changes and latest-successful lookup. Cross-workflow artifact discovery was rejected because it adds candidate and retry ambiguity for no required consumer.

BLD-2. Parallel producers then packaging

Windows and Ubuntu cross/wasm jobs start independently. Ubuntu stages only six raw outputs, Windows uploads its qualified executable, and a short Ubuntu pack job downloads both. Pack never compiles. Same-run checkout identity and named immutable artifacts bind inputs; no cache supplies release binaries. Required producers must succeed before packing. All input and dist artifacts retain 30 days in Release and CI to support retries.

BLD-3. Explicit selection and required results

A MoonBit CI planner compares the PR merge-base with its head using a full checkout and NUL-delimited paths, including deletions and both sides of renames. It preserves the old Release file set and includes the new build workflow and planner. Invalid/missing refs fail planning. Main/manual smoke still uses fingerprint evidence; merge-group smoke remains intentionally skipped. CI aggregate requires all core categories and the planner to succeed, and smoke to succeed exactly when selected. Intentional skips cannot hide required work.

BLD-4. Retry the tested bytes

Keep successful producer and dist artifacts on failed-job retries. Use overwrite for retried producers that uploaded before a later failure. Publish and GitHub release continue consuming the same run's dist after smoke; releases always smoke regardless of cached evidence. PR smoke neither records evidence nor files breach issues.

Migration plan

Land workflow and script changes atomically. Existing production runs retain their original job graph and artifacts. Roll back the source change to restore both workflows. Validate a real PR preview; validate the shared builder and existing Release planning tests without publishing a new version. Archive only in a separate requested workflow.

Assessment

Build/release artifact errors have high impact and must be caught before merge and promotion. Owner is Smithy maintainers, categories are CI and Release. No assurance moves to a later cadence. Hard requirements are provisionally satisfied by this design; artifact transfer, selectors and recovery need verification before adoption.
